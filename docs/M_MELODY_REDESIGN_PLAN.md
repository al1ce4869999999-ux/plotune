# DJぽっぽ｜M系主旋律生成エンジン再設計計画 v1.0

## 目的
理論的な自然さだけでなく、特徴・記憶性・期待と意外性・感情表現を備えた主旋律を生成する。既存M1〜M7、Phase、R系を活用し、大型AIモデルは新設しない。

## 設計原則
1. 音符より先に主題の特徴（リズム、輪郭、アクセント、休符、特徴音）を計画する。
2. M1で複数候補を生成し、自然さの最低条件を満たす候補から識別性・反復可能性で選択する。
3. 主題IDに重要特徴を記録し、後段の変更で保持する。
4. M2は主題の同一性を守りながら感情変奏する。
5. M3は重要音を機械的に和音構成音へ変更せず、和音側の調整や非和声音の保持も比較する。
6. Phase・Rは提示・発展・対比・回帰を管理する。
7. M7の自動指標と人間の聴取評価を分ける。

## 処理責務
Phase（構造・感情計画）→ M1（主題候補生成・選択）→ M2（感情変奏）→ M3（和声協調）→ Phase/R（発展・回帰）→ M4〜M6（声部・演奏・編曲）→ M7（評価）。
これは論理的責務。実際の呼び出し順は既存コードを確認して互換性を維持する。

## 改修仕様
### M1
既存生成器を利用し、初期値6候補（設定可能）を同一seedで再現可能に生成する。リズム識別性、旋律輪郭、重要な跳躍・休符、反復可能性、自然さを評価する。
### 主題ID
リズムパターン、輪郭、特徴音、重要休符、終止方向を記録する。変奏ごとに維持必須の特徴を指定する。
### M2
音程跳躍平均・休符率などの局所統計に加え、主題同一性を評価する。音価・間・抑揚・緊張持続を使って感情を表現する。
### M3
主題重要音の変更を最小化し、和音変更、非和声音の保持、経過音接続を比較する。PR #94の和声整合性修正を維持する。
### Phase・R
主題IDをセクション間で継承し、完全反復・リズム変奏・音程変奏・対比・回帰を区別する。
### M4〜M7
既存の声部・演奏・編曲・聴取比較との互換性を維持する。

## 評価
自動評価軸：リズム識別性、旋律輪郭、主題同一性、期待と意外性、和声整合性、フレーズ自然性。
これらは記憶性の代理指標であり、実際の好み・記憶性を保証しない。
人間の聴取評価：好き/嫌い、記憶に残る/残らない、予想通り/意外、自然/不自然を独立に評価する。

## 実装順・完了条件
1. M1候補生成・選択：同一seedで再現可能な候補選択。
2. 主題特徴保護：変奏後も指定特徴を保持。
3. M2・M3改修：重要音の不要な変更を防止。
4. Phase・R接続：主題の提示・発展・回帰が成立。
5. M7聴取比較：同一和声・伴奏・音色で従来版と比較し、記憶性・個性が改善し自然さが著しく悪化しない。

## 開発制約
- GitHub Actions禁止。関連する既存ローカルテスト優先。新しい大規模テスト基盤は作らない。
- PR #94の和声整合性、既存のフェードアウト・終止処理、M7比較機能を維持。
- 無関係なUI・音色・編曲を変更しない。小さく分割して実装。
- 影響テスト：M1、motif planner、M2、M3、Phase、R1〜R4、M4〜M7、R0固定baseline（実際の構成を確認して絞る）。
- 着手前にPR #94の生成呼び出し順、R3/R9接続、既存テスト範囲を確認する。

## 完成判定
技術的完成：候補生成・選択・特徴保持、後段への主題情報継承、既存機能互換、seed再現性、必要なローカル回帰確認。
音楽的完成：人間のA/B聴取で記憶性・個性の改善が確認され、自然さが著しく悪化しない。技術実装のみで音楽性改善完了とはしない。
