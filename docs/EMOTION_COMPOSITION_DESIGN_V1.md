# plotune 感情誘発型・階層的自動作曲システム 設計書 v1.0

- **状態:** 採用済み（基本設計）／実装・聴取検証は別途
- **採用日:** 2026-10-22
- **目的:** さまざまな感情を呼び起こす音楽性を持つ楽曲の自動生成
- **対象:** plotune の共通旋律・和声・リズム・編曲・評価の生成系
- **設計原則:** 既存エンジンを維持・拡張し、小さな変更と回帰確認を重ねる

## 1. 目標と非目標

### 目標
1. 喜び・悲しみのような単一ラベルにとどまらず、複合的で時間変化する感情体験を意図した音楽を生成する。
2. 旋律・和声・リズム・音色・編成・楽曲構造を相互に関連付け、楽曲の一貫性と多様性を両立する。
3. 音楽的な期待、反復、変奏、緊張、解決、間を通じて表現方法の選択肢を増やす。
4. 音楽理論上の整合性と、人間が聴いて感じる感情・自然さを区別して評価する。
5. 同じ感情目標でも異なる音楽的な解釈・作品が生まれるようにする。

### 非目標
- 特定ゲーム音楽、楽器、ジャンルの模倣を最終目的としない（それらは表現手段）。
- 「悲しい＝短調で遅い」などの固定対応を唯一の生成規則にしない。
- 感情パラメータと聴取者の実感が必ず一致すると断定しない。
- 自動スコアだけで楽曲の良し悪しを確定しない。

## 2. 理論的な基盤と実装上の扱い

- **GEMS (Geneva Emotional Music Scale):** 音楽に関連する感情の9因子を参考に、驚嘆・超越感・優しさ・郷愁・安らぎ・力強さ・活発な喜び・緊張・悲しみを、重複可能な連続値として保持する。因子をそのまま人間の内面の測定値とみなさない。
- **多次元の補助変数:** 快／不快、覚醒度、緊張度、期待度などを追加する。心理学的尺度と作曲の制御変数は区別する。
- **感情誘発経路:** BRECVEMA等の研究を参照し、期待、表情的特徴、記憶の連想など複数の経路が存在することを前提とする。ただし個人の記憶による作用を音楽特徴だけで直接制御できるとは仮定しない。
- **音楽生成:** 動機の反復・変奏、階層構造、和声と旋律の整合、緊張・解決の時間変化を扱う。

研究参照先（採用の根拠候補。実装時に各研究の適用範囲を再確認すること）:
- GEMS: https://www.gemsmusic.net/
- Juslin の音楽感情誘発研究（BRECVEMA）
- MusicFrameworks: https://arxiv.org/abs/2109.00663
- MorpheuS: https://arxiv.org/abs/1812.04832

## 3. 全体アーキテクチャ

```text
感情目標モデル
    ↓
楽曲構造プランナー
    ↓
統合作曲エンジン（旋律 ↔ 和声 ↔ リズム）
    ↓
編曲・音響エンジン（楽器の役割・音色・強弱・休止）
    ↓
品質評価（構造／整合／多様性／目標整合）
    ↓
局所修正・聴取フィードバック
    ↳ 必要な上流工程へ差し戻す
```

各層が同一の計画ID・セクションID・動機IDを参照できるようにする。生成経路が違っても基本データモデルを共有し、楽器固有の演奏特性は維持する。

## 4. 各モジュール

### 4.1 感情目標モデル
- 楽曲全体と各セクションに複数感情の強度（0〜1）を保持する。
- キーフレームや区間目標により、滑らかな推移・急変・共存を指定できる。
- 「作曲に対する目標値」と「聴取者の主観評価」を別スキーマにする。
- 感情ラベルは将来的な拡張に耐える形にする。

### 4.2 楽曲構造プランナー
- 既存のフェーズ1の構造設計を拡張する。
- セクションの役割（提示・反復・変奏・対比・回帰・終結）、長さ、動機の関係、緊張度、密度、感情目標を記録する。
- ABA等の固定形式のみにはしない。
- セクション遷移には、つながりの理由（動機・和声・リズム・編成）を最低一つ与える。

### 4.3 統合作曲エンジン
- **旋律:** 動機・輪郭・音域・リズム・休符・終止・変奏を扱う。
- **和声:** 旋律の着地点、和声機能、非和声音、転調・借用などを必要に応じて扱う。
- **リズム:** 拍節感、反復、シンコペーション、余白、伴奏との関係を設計する。
- 三者を完全に独立した乱数生成にせず、共通のセクション目標で協調させる。
- 「緊張を増す＝音高を上げる」に固定せず、和声・リズム・密度・期待の変化など複数の手段を選択する。

### 4.4 編曲・音響エンジン
- 楽器の役割：主旋律、応答、和声支援、リズム支援、対旋律、音響演出。
- 役割の引き継ぎ、掛け合い、休止、音域分配をセクションごとに計画する。
- 現行の矩形波・オルゴール・笛・キャラクター曲などの生成経路を維持しつつ、音色、音価、強弱、余韻の可能な範囲を制御する。

### 4.5 品質評価エンジン
評価軸を分離して記録する。
1. **整合性:** 不自然な声部干渉、和声衝突、音域逸脱、フレーズ接続
2. **構造:** 動機の識別性、変奏の関係、セクション遷移、終止
3. **多様性:** 音高・リズム・和声・密度・編成の変化（変化が少ないこと自体を自動で不正解にしない）
4. **計画整合:** 設定した緊張・密度・感情表現上の作曲目標との一致
5. **主観的聴取:** 実際に感じた感情、読み取った感情、自然さ、好み

### 4.6 局所修正とフィードバック
- 問題小節や区間を特定して、必要な範囲だけ再生成する。
- 動機IDやセクションの不変条件を保持する。
- 元曲と候補を同条件で比較し、ユーザーの聴取評価を記録する。
- 評価の高い候補でも聴取者が不自然と感じる場合は失敗例として残す。

```json
  "version": 1,
  "seed": 12345,

    "tension": 0.2,

  "sections": [
    {
      "id": "A",
      "function": "theme",
      "motifIds": ["m1"],

      "density": 0.4
    },
    {
      "id": "B",

```

これは基本構造の例であり、実際のフィールド名・型・永続化方法は既存の生成契約を確認してから決定する。シード固定による再現性は可能な範囲で確保する。

## 6. 実装計画と完了基準

| Phase | 内容 | 完了基準 |
|---|---|---|
| 1 | 感情目標と既存の楽曲構造を接続 | 区間ごとの複合目標と変化が計画・生成結果に追跡可能 |
| 2 | 旋律・和声・リズムの共同制御 | 同一動機から、音高差だけでない複数の展開を生成可能 |
| 3 | 楽器の役割・音響表現の連動 | セクションの変化に応じて楽器の出入りと役割を制御可能 |
| 4 | 品質評価と局所再生成 | 対象区間だけを修正し、全曲構造を維持可能 |
| 5 | 聴取評価と改善ループ | 生成計画・音源・主観評価・比較条件を対応付け可能 |

## 7. 比較・検証方針

- **技術検証と聴取検証を分ける。** CI成功やデプロイREADYを聴き比べの成功とみなさない。
- 新旧比較では、同一シード・同一編成・同一条件を記録し、実際にそれぞれの音を再生可能な画面を提供する。
- 聴取アンケートでは「感じた感情」と「表現されていると読み取った感情」を別々に聞く。自然さ・好みも別に記録する。
- ユーザーが比較できる最新デプロイと対象コミットを紐付ける。
- 変更時の回帰対象：通常作曲、オルゴール、笛、キャラクター曲、共通旋律、フレーズ、和声連動、構造生成、比較再生。
- 実装前に既存のテスト名とCI環境を調べ、影響範囲を最小化する。

## 8. 運用ルール

- この文書は採用済みの**基本設計**。具体的な音楽心理モデルの係数・実装方針・UIは検証により改訂する。
- 「提案」「実装済み」「CI成功」「実機確認」「聴取評価済み」を混同しない。
- 不具合は問題、再現、原因（確度）、修正、前後の結果、未解決事項をIssueに記録する。
- 変更は小さく行い、既存の作曲経路を壊さない。必要な場合は段階的な切り替えフラグを用いる。
- 最終評価は音楽的・感情的な品質で行う。

## 9. 最初の開発タスク

1. 現行の楽曲構造・感情パラメータ・生成インターフェースと既存テストを棚卸しする。
2. 既存契約と互換性のある、複合感情・時間推移の計画データを設計する。
3. 一曲内で少なくとも二つのセクションに異なる感情目標を伝播させる最小変更を行う。
4. シード固定の旧方式／新方式の再生比較を用意する。
5. CI確認と実際の聴取評価を別記録にする。

---
**正式決定:** plotune の中心目標は「さまざまな感情を呼び起こす音楽性」であり、特定のゲーム音楽や楽器の再現に限定しない。
