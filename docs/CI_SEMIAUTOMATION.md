# CI成功後の半自動マージ（opt-in）

## 運用

- 通常のPRは自動マージしない。
- **main宛のPRに `ci-automerge` ラベルを付けた場合のみ**、`Plotune engine tests` が成功した後で自動マージを試みる。
- 実行時点で、PRがopen・非Draft・最新コミット一致・全報告チェック成功であることを確認する。未完了や失敗があればマージせず停止。
- GitHub側のブランチ保護・必要レビューは引き続き適用される。保護条件によりマージが拒否される場合もある。
- 他のチェックがCIより後に終わった場合は自動再実行されない。その場合はPR上で手動マージ、またはCI再実行が必要。
- PRが別PRをbaseとする積み重ね構造ではラベルを付けない。先に依存PRをmainへ統合し、baseをmainに変更してから判断する。
- Safari Preview・実機挙動・試聴など**人の判定が必要なPRにはラベルを付けない**。
- 自動マージを停止したい場合はラベルを外す。イベント実行と同時だと競合する可能性があるためマージ前のPR状態も確認する。

## 通知と次工程

GitHub通知は引き続きCI成功/失敗の確認に利用する。Actions通知の細かさは個人設定側で調整し、ワークフローから追加の通知やコメントを大量に送らない。

この半自動化はGitHub上のマージまで。ChatGPTがGitHubのイベントで自動起動して次の実装をするものではない。次の工程は会話で「続けて」と指示して進める。

## 導入後に確認すること

1. GitHub Actionsで新ワークフローが有効になっていること。
2. 書き込み権限のポリシーやmain保護規則によってマージが拒否されないか。
3. 非対象PRがマージされないこと、ラベル付きのCI成功PRのみ動作すること。
4. 既存の `.github/workflows/test.yml` の結果を変更していないこと。

実際のCI/PRでの動作検証完了までは、導入だけで「動作確認済み」とは扱わない。
